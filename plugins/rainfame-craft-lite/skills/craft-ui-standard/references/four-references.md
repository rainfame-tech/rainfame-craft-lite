# The four references as rules

Map each line to a concrete rule for the product being built.

## NN/g's 10 usability heuristics
1. Visibility of system status: every save shows a result within 400ms; the shell stays on screen while a page loads.
2. Match with the real world: the user's words; local dates, times and currency.
3. User control and freedom: every sheet and form has Cancel; destructive actions confirm and say what will happen; records can be corrected, never silently overwritten.
4. Consistency and standards: one name per feature; one Section component; the same row, mark and money patterns everywhere.
5. Error prevention: refuse impossible actions before they happen; sensible defaults.
6. Recognition rather than recall: names, dates and next steps on screen; no ids or codes.
7. Flexibility and efficiency: one persistent Add action; frequent tasks in two taps or fewer.
8. Aesthetic and minimalist design: one primary action per screen; nothing the user cannot act on or needs to know.
9. Recognise, diagnose, recover: plain errors with the next step.
10. Help and documentation: help at the point of need through purpose lines.

## Apple Human Interface Guidelines (applied on the web)
- Targets at least 44 by 44 points; primary actions in the bottom third at 375px.
- Bottom tab bar of three to five labelled destinations, always visible.
- Sheets for short focused tasks with a title, Cancel and one confirm.
- Safe areas respected; system text size and reduced motion respected.
- Clarity, deference, depth: content first, chrome quiet, hierarchy from type and spacing rather than boxes.

## Material Design 3
- 4px grid and fixed spacing steps.
- Type roles mapped to the scale.
- State layers: hover, focus and pressed change more than colour; a visible focus ring on every interactive element.
- Colour roles with dark values.
- Elevation through tonal surfaces and hairlines, not heavy shadows.

## Laws of UX
| Law | Rule |
| --- | --- |
| Jakob | Use patterns users know from phone apps: tabs, lists with chevrons, sheets. |
| Fitts | Big targets near the thumb for frequent actions; destructive actions small and away. |
| Hick | Five tabs at most; one primary action per screen. |
| Miller and chunking | Sections of seven or fewer before See all. |
| Tesler | The app carries the complexity; the screen shows one plain sentence. |
| Proximity and common region | Group by space and shared surface; no box in a box. |
| Similarity | The same kind of thing always looks the same. |
| Von Restorff | One strong element per screen. |
| Serial position | Most important items first and last. |
| Doherty threshold | Feedback within 400ms; skeletons while loading. |
| Goal-gradient and Zeigarnik | Counts that shrink as work is done; unfinished work kept. |
| Peak-end | Finish tasks on a calm, specific confirmation. |
| Aesthetic-usability | Craft details matter: rhythm, aligned figures, no colour flash. |
| Postel | Accept varied input; show it consistently. |
| Active user | No tutorial walls; screens explain themselves. |
| Pareto | Polish the daily 20% first. |
